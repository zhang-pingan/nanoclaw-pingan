# Dynamic Workflow Contract Pack

This directory is the machine-readable authority for Dynamic Workflow Runtime contracts. G0.2 provides the common artifact envelope, exact `VersionedRef`, strict JSON, canonical/domain-separated SHA-256, foundation fixtures, and the conformance entry point. G0.3 adds closed Definition, Recipe, Runtime Command, Transition, Feature Manifest vNext, Card Presentation, Source IR, and Compiled IR schemas with TypeScript key/union conformance and positive/negative fixtures. G0.4 adds closed Compiler Error, Runtime Fact/Event, Permission, Command Reason/Denial catalogs; runtime state transition tables; the command authorization table; and the declarative T0-T8/T6e transaction protocol table. G0.5 adds the immutable `local_single_user_safety@1`, closed hot-reload Capacity baseline, Product Floor, Retention policy, complete per-field Enforcement Matrix, and the explicitly uncertified `local_single_user_sqlite@1` candidate. G0.6 adds the canonical metadata source for all 74 Normative Logical Schema objects, complete expanded column metadata, internal typed relations, explicit external-reference validators, CHECK/UK/FK/index intent, and the fixed query intent catalog. G0.7 adds the machine-generated `WorkflowRuntimeAbsenceBaseline`, `ProductSurfaceCoverageManifest`, and `MigrationCandidateBoundaryManifest`. G0.8-G0.10 and R-016 remain construction provenance from the original gate sequence. The G2 semantic-correction Contract, per-case inputs, actual Compiler candidate, and working review bundle remain the exact, non-publishable `WORKING` source set. The explicit `prepare-rc` entry freezes those four roots into the single `conformance/review-candidate/g2-semantic-correction/` Review Candidate. The RC is `RC_REVIEW`, non-publishable, Production-unreachable, and invalidated by any bound source/toolchain/compiler/Working identity drift. It does not create a Draft v5/v6 or an additive RC chain. Draft v3/v4 review history is retained only by Git commit history and is absent from the active dependency graph; no current Contract/check path reads `.git` or invokes Git history.

`safety/` contains G0.5 contracts. `sqlite/` contains the G0.5 SQLite candidate plus G0.6 logical metadata artifacts. `static/` contains the three G0.7 closed schemas and generated manifests. The SQLite candidate has null release/native/SQLite observation fields and is not certification evidence. G0.6 records logical type/nullability/relation/constraint/index/query intent only: it contains no SQL text, executable migration, executable Schema Manifest, Supported Limits, Store, connection factory, SQLite open, or PRAGMA execution. G0.7 performs absence-only SQLite schema inspection and does not execute Runtime SQL or migrations. Historical G0/R-016/Draft artifacts remain available for explicit construction archive verification. `conformance/sealed/g2-semantic-correction/` remains the immutable 3.0.0 predecessor oracle and its independent replay remains 29/40. The additive `conformance/sealed/g2-production-compiler-replay-repair-v2/` successor binds the owner-approved 3.0.1 Draft, review report, and GoldenSemanticReview into a complete 157-artifact bundle. The current independent Production Compiler replay targets that approved successor and is 40/40 exact. Both bundles are non-publishable and Production-unreachable; no Publisher or G3+ artifact is created by the G2 seal or replay commands.

`contracts:generate` regenerates the current G2 Working Contract/input/candidate/review bundle and current Schema artifacts; it never prepares an RC, creates an approval, or updates sealed expected bytes. G3 artifacts have separate `contracts:g3:generate`, `contracts:g3.registry:generate`, `contracts:g3.query:generate`, `contracts:g3.6:generate`, `contracts:g3.2a:generate`, and `contracts:g3.2:generate` entries so a G2 generation command cannot write them implicitly. `contracts:check` validates the unchanged predecessor Working/RC/Draft/report/review/seal identities, the additive successor Draft/report/GoldenSemanticReview/seal hash chain, and the deterministic G3.1, G3.3, G3.5, G3.6, G3.2A, and G3.2 packs. After seal, construction-era G0.10, Working, and RC roots are checked from their frozen artifact inventories instead of re-running obsolete "sealed must be empty" assertions. `golden:current:replay:check` is the separate Production Compiler gate for the approved successor and requires 40/40 exact equality.
