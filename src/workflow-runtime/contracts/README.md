# Dynamic Workflow Contract Pack

This directory is the machine-readable authority for Dynamic Workflow Runtime contracts. G0.2 provides the common artifact envelope, exact `VersionedRef`, strict JSON, canonical/domain-separated SHA-256, foundation fixtures, and the conformance entry point. G0.3 adds closed Definition, Recipe, Runtime Command, Transition, Feature Manifest vNext, Card Presentation, Source IR, and Compiled IR schemas with TypeScript key/union conformance and positive/negative fixtures. G0.4 adds closed Compiler Error, Runtime Fact/Event, Permission, Command Reason/Denial catalogs; runtime state transition tables; the command authorization table; and the declarative T0-T8/T6e transaction protocol table. G0.5 adds the immutable `local_single_user_safety@1`, closed hot-reload Capacity baseline, Product Floor, Retention policy, complete per-field Enforcement Matrix, and the explicitly uncertified `local_single_user_sqlite@1` candidate. G0.6 adds the canonical metadata source for all 74 Normative Logical Schema objects, complete expanded column metadata, internal typed relations, explicit external-reference validators, CHECK/UK/FK/index intent, and the fixed query intent catalog. G0.7 adds the machine-generated `WorkflowRuntimeAbsenceBaseline`, `ProductSurfaceCoverageManifest`, and `MigrationCandidateBoundaryManifest`. G0.8 adds the unsealed Compiler Golden Draft, complete test-only input snapshots, hand-authored diagnostic and normalized-semantic assertions, and immutable pending review request/report input. G0.9 is retained as an immutable historical exit root. G0.10 publishes an additive Capacity control-plane root with the closed publication and admin-command schemas, independent permission/reason/denial catalogs, CAP0-CAP4 protocol and recovery boundaries, Logical Schema and Scheduler Admission lineage delta, Markdown coverage, inventory, Gate review, and positive/negative/fault fixtures.

`safety/` contains G0.5 contracts. `sqlite/` contains the G0.5 SQLite candidate plus G0.6 logical metadata artifacts. `static/` contains the three G0.7 closed schemas and generated manifests. The SQLite candidate has null release/native/SQLite observation fields and is not certification evidence. G0.6 records logical type/nullability/relation/constraint/index/query intent only: it contains no SQL text, executable migration, executable Schema Manifest, Supported Limits, Store, connection factory, SQLite open, or PRAGMA execution. G0.7 performs absence-only SQLite schema inspection and does not execute Runtime SQL or migrations. `conformance/draft/` contains G0.8 candidate inputs only; `conformance/sealed/` remains reserved and contains only `.gitkeep`. G0.8 does not contain approved `GoldenSemanticReview`, reviewed Plan/proof/program bytes or hashes, a Golden Bundle, `golden-seal`, or a Production Compiler. `conformance/g0-exit/` contains only the historical G0.9 coverage, inventory, Gate review, schemas, and fixtures. All generated G0.10 JSON, including its root manifest and independent domain catalog, is isolated under `conformance/capacity-control-plane-addendum/`. G0.3 fixtures live under `conformance/closed-schemas/`, G0.4 fixtures under `conformance/catalog-protocols/`, G0.5 fixtures under `conformance/safety-sqlite/`, G0.6 fixtures under `conformance/logical-schema/`, and G0.7 fixtures under `conformance/static-absence/`. The protocol, profile, logical-schema, static-gate, Golden Draft, G0 exit, and Capacity addendum artifacts do not implement Store, Registry, Compiler, or Runtime semantics.

Use the managed toolchain for both commands:

```bash
./scripts/runtime-toolchain.sh exec -- npm run contracts:generate
./scripts/runtime-toolchain.sh exec -- npm run contracts:check
./scripts/runtime-toolchain.sh exec -- npm run test:g0
```

`contracts:generate` refreshes G0.2-G0.8, verifies the G0.9 root/generator/member/prior/Capacity identities without writing them, and then generates G0.10. `contracts:check` performs the same historical verification and checks G0.10 byte-for-byte without writing. G0.7 derives its evidence from the TypeScript AST/import graph, Web route enumeration, Electron DOM inventory, Feature manifest parser, SQLite schema inspection, and configured filesystem roots. Migration candidate bytes are read only by the checksum verifier and never enter source-hit analysis. G0.8 writes only deterministic Draft inputs and uses strict parse, generic JCS, and domain-hash helpers; it does not import or call a Production Compiler, normalizer, lowerer, or proof implementation. G0.9 remains the immutable historical root and continues to prove that the newly added publication format is drift relative to its old Markdown closure; G0.10 owns the additive delta coverage. CI runs the complete `test:g0` entrypoint and fails on contract drift, incomplete Compiler case coverage, raw/snapshot/inventory hash drift, forged reviewed output or approval, sealed-directory writes, prior-pack identity drift, invalid Capacity authority/delegation/CAS/recovery semantics, or invalid downstream Gate status. G0.2-G0.9 manifests remain byte-identical and are exact-pinned by G0.10.
