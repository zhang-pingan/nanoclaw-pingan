# Dynamic Workflow Contract Pack

This directory is the machine-readable authority for Dynamic Workflow Runtime contracts. G0.2 provides the common artifact envelope, exact `VersionedRef`, strict JSON, canonical/domain-separated SHA-256, foundation fixtures, and the conformance entry point. G0.3 adds closed Definition, Recipe, Runtime Command, Transition, Feature Manifest vNext, Card Presentation, Source IR, and Compiled IR schemas with TypeScript key/union conformance and positive/negative fixtures. G0.4 adds closed Compiler Error, Runtime Fact/Event, Permission, Command Reason/Denial catalogs; runtime state transition tables; the command authorization table; and the declarative T0-T8/T6e transaction protocol table. G0.5 adds the immutable `local_single_user_safety@1`, closed hot-reload Capacity baseline, Product Floor, Retention policy, complete per-field Enforcement Matrix, and the explicitly uncertified `local_single_user_sqlite@1` candidate. G0.6 adds the canonical metadata source for all 74 Normative Logical Schema objects, complete expanded column metadata, internal typed relations, explicit external-reference validators, CHECK/UK/FK/index intent, and the fixed query intent catalog. G0.7 adds the machine-generated `WorkflowRuntimeAbsenceBaseline`, `ProductSurfaceCoverageManifest`, and `MigrationCandidateBoundaryManifest`. G0.8-G0.10 and R-016 remain construction provenance from the original gate sequence. The G2 semantic-correction Contract, per-case inputs, actual Compiler candidate, and working review bundle remain the exact, non-publishable `WORKING` source set. The explicit `prepare-rc` entry freezes those four roots into the single `conformance/review-candidate/g2-semantic-correction/` Review Candidate. The RC is `RC_REVIEW`, non-publishable, Production-unreachable, and invalidated by any bound source/toolchain/compiler/Working identity drift. It does not create a Draft v5/v6 or an additive RC chain. Draft v3/v4 review history is retained only by Git commit history and is absent from the active dependency graph; no current Contract/check path reads `.git` or invokes Git history.

`safety/` contains G0.5 contracts. `sqlite/` contains the G0.5 SQLite candidate plus G0.6 logical metadata artifacts. `static/` contains the three G0.7 closed schemas and generated manifests. The SQLite candidate has null release/native/SQLite observation fields and is not certification evidence. G0.6 records logical type/nullability/relation/constraint/index/query intent only: it contains no SQL text, executable migration, executable Schema Manifest, Supported Limits, Store, connection factory, SQLite open, or PRAGMA execution. G0.7 performs absence-only SQLite schema inspection and does not execute Runtime SQL or migrations. Historical G0/R-016/Draft artifacts remain available for explicit construction archive verification. `conformance/sealed/` remains reserved and contains only `.gitkeep`; no Working artifact contains an approved `GoldenSemanticReview`, independently authored expected result/Plan/proof/program bytes, a Golden Bundle, `golden-seal`, or a publishable Production resource.

Use the managed toolchain for both commands:

```bash
./scripts/runtime-toolchain.sh exec -- npm run contracts:generate
./scripts/runtime-toolchain.sh exec -- npm run contracts:check
./scripts/runtime-toolchain.sh exec -- npm run contracts:archive:check
./scripts/runtime-toolchain.sh exec -- npm run test:g0
./scripts/runtime-toolchain.sh exec -- npm run test:g2:contract
./scripts/runtime-toolchain.sh exec -- npm run test:g2:working
./scripts/runtime-toolchain.sh exec -- npm run prepare-rc
./scripts/runtime-toolchain.sh exec -- npm run prepare-rc:check
./scripts/runtime-toolchain.sh exec -- npm run test:g2:prepare-rc
```

`contracts:generate` regenerates the current G2 Working Contract/input/candidate/review bundle and current Schema artifacts; it never prepares an RC. `prepare-rc` is the only RC write entry and installs the single four-artifact RC tree atomically. Repeating it with identical bytes is idempotent; an existing conflicting tree fails closed. `prepare-rc:check` is the strict read-only RC entry: it fails when no RC exists and recomputes every binding when one does. The lifecycle-aware `contracts:check` validates all four Working roots and the `WORKING` boundary when no RC exists; when an RC exists it strictly validates the unique RC and every binding, and never downgrades a damaged, conflicting, or identity-drifted RC to `WORKING`. `contracts:archive:check` remains the explicit construction-history entry point for historical G0/R-016/Draft evidence. Current G1 schema generation and Store startup continue to use the closed eight-member Schema Dependency Manifest, so this construction transition does not alter the physical schema or Production Store identity boundary. Only a later successful fresh independent review may produce the Sealed Golden consumed by Publisher and Production validation.

Some Working directories and TypeScript module names still contain the historical `v4` or `draft` token. Those names are construction-path compatibility only; the generated lifecycle fields are authoritative. The separately frozen RC path has no v5/v6 token and does not convert the Working paths into Published resources. No review, human judgment, approval, signature, seal, or `conformance/sealed/` write is performed by either RC command.
